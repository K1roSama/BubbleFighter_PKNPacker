# 当前支持的 PKN v2

> 2026-10-12 已补原始 EXE 的资源发现、寻址、完整读取和主菜单修改效果实测，见 [客户端实测摘要](ClientValidation.md)。下文此前未实测的说明属于历史阶段；装备页自动操作、广场／地图及独立机器仍待验收。

本格式针对 BubbleFighter KR1304 的 PKN v2，原始加载指令分析样本 BFCLIENT02 的 SHA-256 为 `7ee7872aaeb78104f6b9d81fcb40a0ff4f0fbc9826712f90097c6820bb0f42e4`。本文说明已实现的格式规则；其它客户端版本与 PKN 变体未验证。客户端样本、原始包、汇编分析记录和机器相关证据不包含在源码仓库中。

实际包名与逻辑目录生成小写 `packs/name_00000.pkn`，其 UTF-16 码元和 `s` 决定 headerOffset=`s%312+30`，indexOffset=`headerOffset+(3*s)%212+42`。头和索引分别使用 SNOW 派生流；每条资源的密钥由原始 UTF-16 URI 与索引密钥字段生成。只改变文件名会改变读取位置／密钥，改名必须重新封包。

| 字段 | 磁盘表示 |
| --- | --- |
| 解密头 | uint32 校验、uint8 版本（2）、uint32 条目数、3 字节流补齐 |
| 路径 | uint32 UTF-16 码元数，随后原始 UTF-16LE，不含终止 NUL |
| 元数据 | uint32 校验、flags、相对数据基址的 1024 块偏移、解码大小、存储大小，16 字节密钥 |
| 元数据校验 | 四个 uint32 属性及 16 个无符号密钥字节之和，模 2^32 |
| 数据基址 | 物理索引流结束位置向上按 1024 对齐；索引流按 4 字节读入 |
| flags | 0 普通；1 zlib；2 全加密；3 zlib 后全加密；4 首 1024 字节加密 |

流算法保留原版的有符号 key 字节拼接，以及小端 uint32 的加／减密钥流；它不能直接替换成标准 SNOW 库或 XOR。完整加密的数据按 4 字节补齐，flags 4 只给短于 1024 的加密前缀补齐，后面的明文保持原长度。空资源和零存储长度有原包证据。

索引的 16 字节字段不是必然等于当前正文 MD5 的完整性校验，原包 1157 条目存在反例。工具保留未改内容的原密钥，变更资源用正文 MD5 生成新的合法密钥，以独立 SHA-256 对照判断重封内容一致。

原版发现器枚举 `Packs/*.pkn`，文件名解析从最后的扩展名向前扫描十进制数字，要求前一字符为 `_`。工具接受 ASCII `Name_00000.pkn` 形式，不自动分包。跨包规范化后的重复资源会触发原加载器重复包异常；批量生成前检查参与工作区的最终路径。现有 292 个包合并后 164,542 个查找路径唯一。
