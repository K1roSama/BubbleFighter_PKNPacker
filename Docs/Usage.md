# 图形界面与工作区

PKNPacker 面向 BubbleFighter KR1304 的 PKN v2。首次构建和运行见[构建指南](Build.md)，自动化操作见[命令行参考](CommandLine.md)。

## 浏览与导出

1. 点击“打开 PKN”选择一个或多个文件，或用“扫描目录”打开 `Packs` 目录。
2. 在左侧目录树中选择包或目录，通过路径搜索、扩展名筛选、排序和多选定位资源。
3. 选中文件查看文本或分页十六进制预览；“单文件另存为”导出一个完整文件，“导出选中文件”按来源包保留目录结构。

预览为只读，导出读取完整内容。资源内容使用外部编辑器修改后再导入。

## 编辑与封包

1. **准备内容**：导出后在外部编辑器中修改文件，通过“替换”导入；也可以“完整解包”后直接编辑工作区 `Files` 中的文件。
2. **调整资源集合**：使用“新增”“删除”“撤销操作”登记变更。
3. **检查变更**：确认新增、替换和删除的数量与路径，处理工作区及参与批次的跨包路径冲突。
4. **生成新包**：用“批量封包”输出到独立目录。工具根据输出包名生成索引和数据，完整解码并核对内容 SHA-256，通过后才提交正式文件。

通过“打开工作区”可以继续编辑已有清单；“验证资源包”用于重新读取和解码包。

从目录创建新包时，点击“新建 PKN”，指定输入目录、内部命名空间、输出包名和工作区，检查变更后生成。

## 工作区规则

完整解包后的典型结构：

```text
Extracted/
└── Shader_00000/
    ├── WorkspaceManifest.json    # 来源包、条目与操作记录
    ├── Files/                   # 解包内容，可用外部编辑器修改
    │   └── Shader/Shader.vsh
    └── Changes/                 # 通过工具导入的新增或替换内容
```

| 操作 | 行为 |
| --- | --- |
| 修改 `Files` 中的内容 | 封包时通过 SHA-256 比较识别变更 |
| 删除资源 | 必须显式登记；直接移除文件会报错 |
| 重封已有包工作区 | 始终核验原包，请保留其原路径、包名和内容 |
| 部分解包 | 可继续解包补齐，全部条目完整导出后才能重建完整包 |
| 清单和辅助文件 | 不会写入 PKN |

已有待提交操作时，工具会拒绝再次解包覆盖工作区。撤销恢复原映射，不会覆盖用户在 `Files` 中通过外部编辑器修改的内容。清单字段和内部数据流见[架构说明](Architecture.md)。

## 输出与批量任务

解包遇到已有目标文件默认跳过；封包遇到已有输出默认失败，需要显式允许覆盖。工具禁止将封包输出覆盖到输入原包。

多个独立包默认并行处理，提供进度、逐项结果、取消和失败重试。一个包失败后，其余独立任务继续执行；取消或失败会清理未提交的临时包，已完成的结果保留。

## 包名、路径与兼容范围

| 项目 | 规则 |
| --- | --- |
| 兼容范围 | 面向 KR1304 的 PKN v2；其他客户端版本与格式变体尚未验证 |
| 包名 | 实际包名参与偏移和密钥生成。使用 ASCII `Name_00000.pkn` 形式，改名需通过工具重新封包 |
| 资源路径 | 内部路径支持 UTF-16；查找统一 ASCII 大小写和斜杠，跨包重复路径会产生冲突 |
| 新增资源 | 建议使用独立命名空间，例如 `Images/Custom`；游戏使用新增资源还需要相应引用 |
| 容量限制 | 拒绝 ≥4 GiB 的包、超过 500,000 个条目或写入索引超过 64 MiB；暂不自动分包 |

批量检查覆盖本次参与封包的工作区。替代包投入同一套资源目录时，还需核对未参与本次任务的包，避免与含同路径资源的原包同时加载。

当前验证覆盖工具行为、原包读取和重封内容对照；真实游戏进程中的包发现、资源寻址和界面效果尚未验收。复现方法、便携版启动验证及完整验收边界见[验证说明](Validation.md)。
